# 교사·운영자 작업공간 변경 — 2026-09-07

이 문서는 기능 연결·상태 경계 변경을 기록합니다. 운영 계정에서 모든 API를 실행했다거나 실제 기기 QA를 끝냈다는 판정은 아닙니다.

## 정보 구조

교사 최상위 목적지는 **개요 / 반 / 학생 / 출결 / 더보기**입니다.

- 개요: 승인 대기 바로가기, 오늘 출결, 수업·과제, 기존 학습 분석·확인 필요 학생.
- 반: 반 생성·일정·담임·공동 담당·보관/복구 및 수업·주차·과제·자료.
- 학생: 현재 페이지 이름/학교/반 검색, 상세 통계·학부모 공유, 최대 20명 일괄 작업.
- 출결: 날짜/반/회차, 코드, 상태·메모, 저장.
- 더보기: 교직원, 초대, 학원 범위 유출 추적, 원장 설정.

관리자 최상위 목적지는 **운영 / 학원 / 사용자 / 콘텐츠 / 재무·시스템**입니다.

- 운영: 학원 등록 승인함, 문의·할 일·공지.
- 학원: 전체 학원 검색/상태/페이지 → 계약·구성원·반·주차·출결·감사 상세.
- 사용자: 학생·교사·관리자·보호자, 상태·제재·감사, 활동 및 평가 원본.
- 콘텐츠: 주간 모의, 자료실, 상점, 게시판, 문제은행, 코치 문구.
- 재무·시스템: 환불·페이백, Arena 운영/정책, 월별 지표, PDF 추적, 운영 매뉴얼.

기존 도구 15개와 승인함은 `AdminWorkspaceTool` 16개 case로 연결했습니다. WebView로 대체하거나 서버 기능을 제거하지 않았습니다. 검색은 실제 도구 집합을 대상으로 하며 여러 검색어를 모두 포함하는 항목을 보여 줍니다.

## 컨테이너와 상태 보존

- 1,040pt 이상: 업무 사이드바. 그 아래: 같은 5개 목적지의 고정 하단 탐색.
- 목록–상세는 실제 작업 컨테이너 700pt 이상에서 나란히 표시합니다. 교사 반·학생, 관리자 학원·사용자에 적용했습니다.
- 좁은 화면은 목록 → 상세 → 원래 목록으로 복귀합니다. 목록 검색·선택 모델을 그대로 사용합니다.
- 방문한 교사 패널과 관리자 도구는 동일 view identity로 유지합니다. 패널 전환으로 검색, 페이지, 선택, 스크롤, 초안 모델을 재생성하지 않습니다.
- 관리자 도구는 목적지별 마지막 도구를 기억합니다. 계정이 바뀌면 방문/선택 기록을 초기화합니다.
- 관리자 Arena의 15초 폴링은 해당 패널이 보이고 앱이 foreground일 때만 실행합니다. 다른 retained 도구에는 반복 타이머가 없음을 소스 확인했습니다. 기존 사용자 행동에 따른 일회성 서버 요청은 계속 수행합니다.
- 입력 중 sheet의 취소는 변경 폐기를 확인하고, 처리 중에는 중복 제출/닫기를 막습니다. 이 보존은 현재 앱 세션 범위이며, 관리자 민감 초안을 디스크에 새로 저장하지 않았습니다.

## 실제 수정한 데이터 손실·경합

1. 교사 출결 새로고침/다른 반·날짜 이동으로 초안이 사라지는 문제: 날짜+반+회차별 baseline/edited를 보관하고 3-way merge합니다. 서버와 사용자가 같은 행을 다르게 고쳤다면 저장 전에 충돌 처리를 요구합니다. 명단에서 삭제된 학생은 초안으로 복구하지 않습니다.
2. 로딩 중 이전 날짜의 출결을 저장할 수 있는 문제: 표시 회차와 선택 필터 일치, 로딩 완료, 충돌 해소를 검사합니다.
3. 교사 일반 작업이 실행되지 않았는데 `errorMessage == nil`만으로 성공을 반환하던 문제: 실제 완료 Boolean으로 변경했습니다.
4. 교사 출결/학급/과제/파일 및 관리자 학원/사용자 응답이 계정 전환 뒤 적용되는 문제: 계정 슬롯, 세대, 요청 ID/선택 ID, 인증 snapshot을 확인합니다.
5. 관리자 사용자 목록/상세 응답 역전: 요청 ID를 분리하고 다른 사용자를 고르면 기존 상세를 먼저 비웁니다. 실제 mutation 중 다른 대상 선택은 막습니다.
6. 교사 일괄 작업의 처리 수가 선택 수보다 적어도 전체 성공으로 안내하던 문제: 부분 처리 경고와 재조회 후 남은 대상만 수동 선택하도록 안내합니다. 서버가 대상별 결과를 주지 않으므로 추측해서 자동 재시도하지 않습니다.
7. 관리자 일정/담임/출결 편집기가 서버 응답 전에 닫히는 문제: 서버 성공까지 유지합니다. 거절·네트워크 오류 시 입력과 상세 오류를 유지합니다.
8. 학원명·계약 편집기도 성공 전에 닫지 않으며 변경 검토 후 저장합니다.
9. 교사/관리자 파일 다운로드가 완료 시점의 다른 계정 폴더에 저장되는 문제: 최초 계정 경로와 인증을 고정하고 적용 전에 재검증합니다.
10. 교사 과제 로딩 실패 시 같은 반의 기존 데이터까지 비우는 문제: 같은 반의 자료는 남겨 재시도하고, 다른 반으로 전환할 때만 이전 자료를 비웁니다.
11. 서버가 403으로 권한 회수를 알렸는데 기존 상세/편집이 남는 문제: 교사 학원·학생·과제 및 관리자 승인·학원·사용자 보호 데이터를 폐기하고 재조회 화면으로 돌아갑니다. 관리자 선택 해제/접근 회수에 맞춰 열린 편집·활동 sheet도 닫습니다. 일반 통신 오류에서는 초안을 보존하지만 권한 회수 시에는 보호 데이터를 유지하지 않습니다.

`ServerAPI.swift`의 교사/관리자 학원 wrapper와 `AdminUsersAPI.swift`의 공개 wrapper는 default argument를 호출 지점에서 평가하여 Bearer snapshot을 async hop 이전에 고정합니다. multipart/download도 같은 자격을 명시적으로 전달합니다. 공통 authorizedRequest는 root 작업에서 보강했습니다.

## 위험 변경 검토

공통 `StaffChangeReview`로 **현재값 → 변경값 → 적용 영향 → 지원되는 사유 → 최종 확인**을 표시합니다.

- 교사 반 설정·반 보관.
- 관리자 학원 일정·출석 정책, 담임 이전, 출결 보정, 학원명·계약.
- 관리자 사용자 역할·상태·경고·삭제·보호자 연결 등.

출결 보정의 메모/사유는 기존 서버 API로 보냅니다. 사유 필드가 없는 일정·담임·학원 계약 API에는 가짜 로컬 감사 입력을 만들지 않았으며 화면에 그 계약 제한을 안내합니다. 그 외 기존 서버 감사 이력 화면과 원장/권한 검증을 유지했습니다.

## 현재 검증과 한계

- `run-staff-workspace-contract.sh`: 실제 Swift 실행형 **99개 assertion** 통과. 목적지 소유권, 모든 도구 연결, 복귀/마지막 도구, 초기화, 검색, 컨테이너 임계, 초안 병합/충돌/학생 삭제를 검증합니다.
- 기존 native-admin 13개 스크립트 및 hosted-service parity 통과. 메뉴 문자열 검사는 새 typed registry 위치로 이동했고 기존 API/fixture/네이티브 도구 존재 검사는 유지했습니다.
- 변경 Swift 파일 parse 통과. 전체 앱 타입 검사/빌드는 root 통합 검증에서 별도 기록합니다.
- 실제 교사·관리자 운영 계정의 권한 회수/서버 거절, 대량 작업 부분 성공, 다른 기기 출결 동시 편집을 E2E 실행한 결과는 아닙니다.
- 실제 기기 회전/Stage Manager/폼 터치 스크린샷과 제출 가능 판정은 통합 QA 증거를 확인해야 합니다.
- 완전한 backend optimistic concurrency/version 또는 대상별 bulk receipt가 없으면 클라이언트만으로 외부 동시 변경을 원자적으로 보장할 수 없습니다.
- 관리자 세부 도구 전부를 동일한 list/detail로 전면 재설계한 것은 아닙니다. 이번 변경의 공통 업무 셸과 목록–상세 적용 대상은 위에 한정했습니다.

웹/서버 저장소는 변경하지 않았고 이 작업에서 커밋·푸시·외부 운영 데이터 변경을 하지 않았습니다.
